# Homelab

Домашний сервер: один узел Kubernetes (k0s), на котором живут сервисы и их базы
данных. Репозиторий ведётся как учебный проект по production-практикам DevOps.

## Language

### Кластеры

**Кластер k0s**:
Единственный узел Kubernetes, на котором живёт всё.
_Avoid_: «кластер» без уточнения, «Kubernetes-кластер».

**Кластер баз**:
Один инстанс PostgreSQL под управлением оператора CNPG: своя версия,
расширения, WAL, PVC, политика бэкапа и окно обслуживания.
_Avoid_: «кластер» без уточнения, «Postgres-кластер».

### Владение

**Граница владения**:
Namespace как единица владения: им владеет ровно один сервис или платформа.
Не разграничивает среды — только ответственность.

**Сервис**:
Деплоируемая единица, которой принадлежит свой namespace и, если нужно, база.
_Avoid_: «приложение» для инфраструктурных сервисов.

**Приложение**:
Сервис для конечного пользователя (Immich, Forgejo, Jellyfin), в отличие от
инфраструктуры и наблюдаемости.

**Платформенный компонент**:
Сервис, который обслуживает сам кластер k0s: трафик, хранилище, секреты,
операторы, GitOps. Лежит вне `apps/`.
_Avoid_: «инфраструктурное приложение».

### Трафик

**Маршрут**:
Одно объявление о том, какой хост какому сервису отдаётся: `HTTPRoute` в
`apps/<сервис>/k8s/route.yaml`. Лежит рядом с приложением, которому принадлежит,
а не в общем каталоге платформы.
_Avoid_: «ингресс», «правило Traefik», когда речь о маршруте.

**Слушатель**:
Имя и адрес, на котором `Gateway` принимает трафик: `https` для
`*.<домен>`, `apex` для самого домена. Wildcard не покрывает apex, поэтому
слушателей два.
_Avoid_: «точка входа Traefik» — вход теперь Gateway, а Traefik его реализует.

**Реализация Gateway**:
Контроллер, который обслуживает `Gateway` и `HTTPRoute`. У нас это Traefik:
`GatewayClass` с `controllerName: traefik.io/gateway-controller`.
_Avoid_: «ингресс-контроллер» — это устаревшее имя для `Ingress`, который
больше не используется.

**Общий middleware**:
`Middleware` Traefik из `platform/traefik/`, копия которого лежит в namespace
каждого потребителя: `ExtensionRef` в `HTTPRoute` ищет его рядом с маршрутом,
а не в `traefik`.
_Avoid_: «общий middleware кластера» — общее только тело, объектов в кластере
столько, сколько namespace'ов-потребителей.

### Базы данных

**Общий кластер**:
Кластер баз с несколькими потребителями; живёт в нейтральном `databases`.

**Выделенный кластер**:
Кластер баз с одним потребителем; живёт в namespace этого сервиса.

**Единица общей судьбы**:
То, что потребители кластера баз обязаны делить: версия, расширения, blast
radius, профиль нагрузки, политика бэкапа, окно обслуживания. Число кластеров
баз равно числу единиц общей судьбы, а не числу сервисов.

**Служебная база**:
База `app`, которую `bootstrap.initdb` создаёт в каждом кластере баз только
чтобы `initdb` было что создать. Ни один сервис её не использует.

**Роль сервиса**:
Непривилегированная роль PostgreSQL, которой владеет один сервис и которая
владеет его базой.
_Avoid_: суперпользователь `postgres` (зарезервирован оператором CNPG).

**Источник**:
Легаси-деплой в `apps/<сервис>/`, из которого база переносится в кластер баз.
_Avoid_: «старая база».

### Хранилище

**Имя тома**:
`<сервис>-<назначение>` (`forgejo-data`, `lute-backup`):
тип ресурса виден из самого объекта, а второе слово несёт роль тома. Если томов
несколько, различие в назначении (`-data`, `-backup`, `-library`), а не в
нумерации.

**Чужое имя**:
Имя тома, которое формирует не мы, а инструмент: CNPG даёт PVC `<кластер>-<N>`,
оператор MariaDB и чарты — свои. Переименовать их нельзя, поэтому правило имени
тома на них не распространяется.
_Avoid_: попытки привести чужие имена к нашей схеме.

**Политика удержания**:
`Delete`/`Retain` из StorageClass — и только для динамических томов. У PV,
описанных руками, политику задаёт поле самого PV, а класс на неё не влияет.
Разные политики — разные классы (`longhorn` и `longhorn-retain`).
_Avoid_: суффикс `-delete` (дефолт и так Delete), ожидание, что класс
переопределит политику статического PV.

### Среды

**Среда**:
prod/dev/qa. Разводится отдельными кластерами k0s или машинами, не namespace'ами.

**Тестовый стенд**:
Сервис, который держат для проверки, а не для эксплуатации, и снимают после
(authentik).
_Avoid_: «тестовое окружение».

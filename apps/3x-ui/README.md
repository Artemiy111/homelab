# 3x-ui

3x-ui — веб-панель для управления Xray-core. Она создаёт inbound-подключения,
клиентов и подписки, считает трафик, задаёт лимиты и сроки действия, показывает
активные подключения и экспортирует готовые клиентские конфигурации. Поддерживает
VLESS, VMess, Trojan, Shadowsocks, WireGuard, Hysteria2, HTTP/SOCKS и несколько
транспортов, включая TCP, WebSocket, gRPC и XHTTP.

Проект предназначен авторами для личного использования. Панель получает полный
контроль над прокси-конфигурацией, поэтому её нельзя публиковать напрямую в
интернет. В этом репозитории интерфейс доступен только через локальный Traefik,
а Xray получает один заранее опубликованный порт `8443` по TCP и UDP.

Разворачивается чартом из `apps/3x-ui/chart/`:

```sh cluster
helm template xui apps/3x-ui/chart | kubectl apply -f -
```

Чарт самодостаточный: в нём namespace, учётная запись и `VaultAuth`,
`VaultStaticSecret`, PVC, Deployment, NetworkPolicy, HTTPRoute и все три
Service. Единственное значение — `serverIp` в `values.yaml`: в него уходят
`externalIPs` сервисов `xui-egress` и `xui-inbound`. Это тот же адрес, что
`config.serverIp` в `platform/homelab/values.yaml`, поэтому при переезде узла
править нужно оба места.

Панель читает `homelab-config` (`TZ`) из своего namespace — ConfigMap создаёт
платформенный чарт, чарт 3x-ui от него зависит и сам его не создаёт.

## Подготовка

Панель будет доступна по адресу, составленному из `XUI_HOST` и
`XUI_WEB_BASE_PATH` в секретах сервиса, например:

```text
https://xui.example.com/<случайный-путь>/
```

Логин и пароль находятся в тех же секретах: случайный пароль администратора и
случайный URL-путь панели генерируются при инициализации. После первого входа
включить 2FA. Внутренний TLS панели включать не нужно: HTTPS завершается на
Traefik.

## Создание первого inbound

Снаружи доступен только заранее опубликованный порт `XUI_INBOUND_PORT`
(`8443` по умолчанию); добавленный в UI произвольный порт сам по себе снаружи не
появится. Поэтому для первого inbound указать порт из `XUI_INBOUND_PORT`. Один
порт нельзя одновременно назначить двум несовместимым inbound-конфигурациям.

Для подключения через интернет отдельно потребуются:

1. NAT на роутере с выбранного внешнего порта на `<node1-ip>:8443` с нужным
   протоколом TCP и/или UDP.
2. Разрешающее правило firewalld на сервере для `8443/tcp` и/или `8443/udp`.
3. Публичный адрес или DNS-имя, доступное клиенту извне.

Не публиковать порт панели `2053`, домен `XUI_HOST` или Traefik `80/443` на
роутере. Если удалённым клиентам достаточно Tailnet, NAT не нужен, но текущая
привязка inbound-порта к LAN-адресу рассчитана именно на перенаправление с
роутера.

## Egress-прокси (порт 8440)

На порту `XUI_EGRESS_PORT` (по умолчанию `8440`) работает HTTP forward proxy.
Внутри Xray пересылает трафик через VLESS-подключение на внешний сервер в
другой стране. Из кластера прокси доступен по внутреннему DNS-имени
`xui-egress.3x-ui.svc.cluster.local`.

Порт открыт только для namespace `monitoring` (`NetworkPolicy` `allow-ingress`).
С узла путь работает, потому что сервис объявлен с `externalIPs`; из LAN и из
tailnet порт закрыт политикой.

Gatus использует этот прокси для:

- Доставки Telegram-уведомлений (Telegram заблокирован в России).
- Мониторинга доступности самого прокси: HTTP-запрос к `api.telegram.org`
  через `client.proxy-url` показывает реальную задержку маршрута.

## Аутентификация прокси

Прокси работает в режиме `auth: password`, учётная запись одна — `gatus`.
Запись живёт в базе панели: панель не читает её из окружения, поэтому
заводится в UI вручную.

Значение хранится в Vault по пути `kv/3x-ui/@gatus/egress` с ключами
`XUI_EGRESS_USERNAME` и `XUI_EGRESS_PASSWORD` и доставляется в namespace
`monitoring` как Secret `xui-egress`
(`apps/gatus/k8s/vaultstaticsecret.yaml`). Сегмент `@gatus` — потому что кред
выдан отдельному потребителю и должен отзываться независимо от секретов 3x-ui
(`docs/adr/0006-vault-secret-path-layout.md`).

База панели уже содержит запись, созданную при `auth: noauth`. Переключать
auth на неё нельзя: её пароль скомпрометирован, нужна новая пара.

Реквизиты подставляются в URL прокси, поэтому пароль обязан состоять из букв,
цифр и `-`, `_`, `.`. Символы `@`, `:`, `/`, `#`, `%` и пробелы ломают разбор
URL.

Значение существует в двух местах — в базе панели и в Vault, — поэтому ротация
это два шага. Сначала новая пара в UI панели, затем Vault и форс-синк VSO:

```sh
kubectl -n monitoring annotate vaultstaticsecret xui-egress \
  vso.secrets.hashicorp.com/force-sync="$(date +%s)" --overwrite
```

Обратный порядок оставит Gatus без рабочего прокси, и Telegram-уведомления
перестанут ходить.

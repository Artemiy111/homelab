# Jitsi Meet - приватный сервер видеоконференций

URL: `https://meet.example.com/`
Jitsi Videobridge принимает медиатрафик на `<node1-ip>:10000/udp`.

## Rootless-контейнеры

Начиная с `stable-11146` все сервисы запускаются от непривилегированного
пользователя uid/gid 1000 с read-only файловой системой контейнера.

## Состояние

Комнаты живут в памяти и исчезают вместе с перезапуском prosody: записей
конференций Jitsi не ведёт. Конфиги и внутренние сертификаты генерируются при
старте и лежат в `emptyDir`, учётные записи `focus` и `jvb` пересоздаются из
секрета. Перезапуск переживает только учётная запись организатора: она лежит в
томе prosody и заводится руками по `RUNBOOK.md`.

## Качество видео

Веб-клиент запрашивает до `1920x1080`. Для Full HD задан предел `2,5 Мбит/с`
для AV1/VP9 и `3,5 Мбит/с` для VP8/H.264. Адаптивный режим Jitsi остаётся
включённым: фактическое разрешение зависит от камеры, размера плитки участника,
производительности клиента и доступной полосы. Jitsi Videobridge не кодирует
видео заново, поэтому увеличение разрешения нагружает клиентские устройства, а
не CPU сервера.

## Сетевая модель

- TCP `443` завершается на Traefik и передаётся контейнеру `web`.
- UDP `10000` привязан только к LAN-адресу сервера и передаётся `jvb`.
- `JVB_ADVERTISE_IPS=<node1-ip>` сообщает браузерам адрес медиамоста.
- STUN отключён: публичный адрес не нужен в приватной сети с маршрутизацией.
- TURN не настроен. Для гостей без Tailscale понадобится отдельное решение с
  публично доступным JVB либо coturn; просто открыть веб-сайт наружу недостаточно.

SELinux и firewalld не отключать. Если firewalld блокирует UDP `10000` внутри
LAN/tailnet, открыть только этот порт для доверенных зон после проверки текущих
правил.

Учётная запись организатора и проверка — в `RUNBOOK.md`.

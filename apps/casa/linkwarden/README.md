# Linkwarden

Менеджер закладок: сохраняет страницу целиком — читаемый текст, скриншот и PDF, —
поэтому ссылка продолжает открываться, даже когда оригинал исчез. Поиск идёт по
сохранённому содержимому, а не только по названию и тегам.

## Как устроен

Три части, как в upstream-стеке:

- **Приложение** — Next.js-сервер и фоновый воркер в одном поде. Воркер
  запускает headless Chromium из образа: он снимает скриншот, печатает PDF и
  вытаскивает текст.
- **Meilisearch** — отдельный под с индексом. Без него поиск по архиву не
  работает.
- **PostgreSQL** — общий кластер CNPG `shared` в `databases`. Сервис тихий,
  расширений не требует, поэтому выделенный кластер ему не нужен
  (`docs/adr/0002`).

Архив (скриншоты, PDF, сохранённые страницы) живёт на своём томе Longhorn, индекс
Meilisearch — на другом. Тома разные намеренно: индекс восстанавливается
переиндексацией из базы, архив — нет, и удаление одного не должно затрагивать
другое.

## Почему манифесты, а не чарт

Официального Helm-чарта у Linkwarden нет: upstream сопровождает
`docker-compose.yml`, а всё, что есть на GitHub, — неофициальные чарты без
сопровождения. Юнит собран по схеме остальных сервисов: Deployment, Service,
PVC, NetworkPolicy и HTTPRoute, без внешнего чарта, который пришлось бы
форкать.

## Вход

Локальные учётные записи: первый пользователь регистрируется через форму
регистрации. OIDC через Zitadel upstream поддерживает, но переменные
`NEXT_PUBLIC_*` в Next.js запекаются в клиентский бандл при сборке образа, а
официальный образ собран с дефолтными значениями. Поэтому включение SSO — это
своя сборка образа, а не переменная окружения; задача отдельная.

## Браузер и `/dev/shm`

Chromium использует разделяемую память, а в поде `/dev/shm` по умолчанию 64 Mi:
на архивации тяжёлых страниц этого не хватает, и браузер падает. Поэтому в под
приложения смонтирован `emptyDir` в память поверх `/dev/shm`.

## Ограничения

- **Один под.** Том архива `ReadWriteOnce`, поэтому реплик больше одной быть не
  может, а обновление — это короткий простой.
- **Архивация требует интернета.** Без egress под не сохранит страницу; сама
  закладка при этом создастся.
- **Внутренние адреса не архивируются.** `ALLOW_PRIVATE_NETWORK_ACCESS` остаётся
  дефолтным: иначе архиватор по запросу пользователя ходил бы в сервисы
  кластера и LAN, то есть стал бы SSRF-прокси.
- **Бэкапа тома нет.** Пока у Longhorn не настроен backup target, потеря тома
  означает потерю архива; база при этом восстанавливается из бэкапа CNPG, когда
  он появится.

Эксплуатация — в `RUNBOOK.md`.

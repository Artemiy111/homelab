# Trivy Operator Dashboard

Веб-интерфейс к отчётам `trivy-operator`: уязвимости по образам и CVE,
misconfiguration, RBAC-оценки, найденные в образах секреты. Нужен потому, что
штатного UI у оператора нет: отчёты лежат CR'ами `aquasecurity.github.io`, и
читать их через `kubectl get -o json | jq` можно только точечными вопросами.

От дашборда `trivy-operator` в Grafana отличается назначением. Grafana отвечает
на «сколько чего и где» по агрегатам метрик, этот UI — на «что именно нашлось в
этом образе и есть ли фикс». Метрики оператора про конкретные CVE не отдают
вовсе, поэтому дашборд их не заменяет.

## Как устроен

UI читает те же CR, что создаёт `trivy-operator`, через API кластера от своего
ServiceAccount, и ничего не хранит: истории нет, состояние — сами отчёты. Пропал
отчёт — пропала строка в UI; пересоздался — вернулась. Отдельной БД, тома и
бэкапа у сервиса нет.

Права — только чтение `aquasecurity.github.io/*` и `namespaces` кластерного
уровня. Других объектов приложение не видит, поэтому скомпрометированный под не
даёт доступа к секретам кластера.

## Что решено неочевидно

- **Взят готовый проект, а не свой UI и не плагин Headlamp.** Свой UI — это
  поддержка всех видов отчётов и их схем; плагин Headlamp обновлялся последний
  раз весной и проверялся на более старой версии Headlamp — совместимость
  пришлось бы чинить самим.
- **История выключена.** Она требует сайдкар valkey и PVC, а PVC — storageClass,
  которого в кластере нет. Цена решения: UI не покажет, как менялось число
  находок по образу; для этого есть Grafana, где метрики хранятся во
  VictoriaMetrics.
- **Маршрут закрыт `oauth2-proxy`.** У приложения нет своей аутентификации и
  ролей: кто прошёл OIDC, видит все отчёты кластера. Граница доступа — маршрут,
  как у остальных сервисов, а не права в UI.
- **Чарт берётся прямо из git-репозитория проекта.** В Helm-репозитории он не
  опубликован; Argo рендерит чарт из каталога `deploy/helm/...` того же тега,
  что и образ. Тег чарта и дайджест образа фиксированы оба: тег у чужого образа
  может быть перезаписан.
- **Проект приложения — `homelab-cluster-readers`.** Он требует чтения кластера
  без возможности создавать посторонние кластерные объекты: в whitelist проекта
  вписаны конкретные имена ClusterRole, а не вид целиком.

## Ограничения

- Обновление версии ручное: в `values.yaml` меняются тег и дайджест, в
  `Application` — тег чарта.
- Проект живёт на энтузиазме одного мейнтейнера и без релизного цикла Helm;
  сломанный релиз чинится откатом дайджеста, а не ожиданием фикса.
- UI показывает только то, что успел просканировать `trivy-operator`. Если
  оператор остановлен, интерфейс открывается, но данных в нём нет.

Проверка, вход, обновление и удаление — в [RUNBOOK.md](RUNBOOK.md).

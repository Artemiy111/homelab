# vmalert

vmalert — компонент VictoriaMetrics, который оценивает PromQL-правила отдельно от
Grafana. Правила живут в CR `VMRule`, сам процесс читает их по селектору, раз в
интервал опрашивает VictoriaMetrics и отправляет сработавшие алерты в
Alertmanager. У него нет UI и своей базы: состояние алертов хранится в
Alertmanager, а vmalert только переотправляет обновления.

## Зачем он здесь

13 правил из `GrafanaAlertRuleGroup` перенесены в `VMRule` с сохранением выражения,
`for`, `severity` и аннотаций. Для vmalert добавлен лейбл `source="vmalert"`: по
нему Alertmanager отличает эти алерты от тех же правил, которые продолжает
считать Grafana (`source="grafana"`). Если оба источника активны для одного
`alertname`, inhibit-правило Alertmanager глушит копию от vmalert, поэтому в ntfy
не приходит дубликат.

Одно правило из `alerts-logs.yaml` написано на LogQL по Loki — vmalert умеет только
PromQL, поэтому оно осталось в Grafana. Пока старые правила не удалены,
определения существуют в двух местах: это цена параллельного сравнения двух
движков.

## Что изменилось при переносе

Цепочка Grafana `A (PromQL) → B (reduce) → C (threshold)` превратилась в одно
PromQL-выражение. Там, где редьюсер был `max`, добавлена обёртка `max(...) > 0` —
она сохраняет поведение «сработало, если проблема есть хотя бы у одной серии».
Шаблон аннотации `{{ $values.A }}` заменён на `{{ $value }}`, потому что у
Alertmanager нет объекта `$values` из Grafana.

## Ограничения

Нельзя перенести LogQL-правила и правила, использующие не-PromQL источники.
Состояние самого vmalert не сохраняется между рестартами, но оно и не нужно:
Alertmanager хранит активные алерты и тишины сам. Инстанс один, без HA.

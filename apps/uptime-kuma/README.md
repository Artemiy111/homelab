# Uptime Kuma

## Запуск

```sh
bash scripts/bootstrap-platform.sh uptime-kuma
```
> Любые последующие команды `docker compose` этого сервиса требуют того же окружения:
> выполняйте их через `bash scripts/compose-secrets.sh uptime-kuma …` или повторным
> `bash scripts/bootstrap-platform.sh uptime-kuma`.


Завершить первоначальную настройку учётной записи по адресу
`https://kuma.example.com/`. Те же логин и пароль записать в локальный
`.env` сервиса:

```dotenv
UPTIME_KUMA_USERNAME=user
UPTIME_KUMA_PASSWORD='секретный-пароль'
```

Файл `.env` не отслеживается Git и должен иметь права `0600`.
Одинарные кавычки обязательны, если пароль содержит `$`: иначе Docker Compose
попытается подставить переменную окружения и передаст сервису другой пароль.

## Память

Node-процесс Kuma со временем раздувается до гигабайта и больше: кэш heartbeats
держится в памяти для websocket-клиентов, а V8 не возвращает освобождённую
память операционной системе. Поэтому в `compose.yaml` задано
`NODE_OPTIONS=--max-old-space-size=512`: heap ограничен, RSS держится
примерно в два раза меньше прежнего. Если контейнер начнёт перезапускаться по
OOM, значение можно поднять.

## Метрики

Kuma отдаёт Prometheus-метрики на `:3001/metrics`. Доступ — по API-ключу
(Настройки → API Keys, без срока действия): ключ записать в `.env` как
`UPTIME_KUMA_METRICS_API_KEY`, netdata скрейпит их как цель `uptime-kuma`
(см. `netdata/README.md`). После добавления первого API-ключа basic auth на
`/metrics` отключается навсегда.

## Декларативные мониторы

Желаемое состояние находится в `monitors.json`. Gatus (`gatus/config/config.yaml`)
— источник правды: Kuma зеркалит его там, где это возможно, поэтому URL и
ожидаемые статусы мониторов должны совпадать с эндпоинтами Gatus.


Применить конфигурацию:

```sh
docker compose --profile tools run --rm configure
```

Команда идемпотентна: она создаёт отсутствующие мониторы и обновляет изменённые.
Существующие мониторы сопоставляются по имени. Мониторы, удалённые из
`monitors.json`, автоматически не удаляются, чтобы случайно не потерять ручную
настройку и историю проверок.

После изменения конфигурации выполнить команду повторно. Для добавления нового
типа сначала расширить проверку входных данных в `sync-monitors.mjs`.

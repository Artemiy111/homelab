# test-nginx

Тестовая страница: проверка сквозного пути «GitHub → Flux → под → внешний балансировщик → браузер». Своей ценности не несёт, состояния не хранит, при появлении настоящего ingress-контроллера удаляется.

## Как устроен доступ

Балансировщик `nlb-k8s-vm` работает на L4 и про Kubernetes не знает: он умеет только «слушать порт и передавать на `<ip>:<port>` из целевой группы». Поэтому путь такой:

```
клиент :80 → NLB (тот же статический адрес, что у kube-api) → NodePort 30080 на узле → под nginx :8080
```

`Service` типа `NodePort` открывает порт на всех трёх узлах, `kube-proxy` сам направляет трафик к поду, где бы он ни был. Целевая группа у HTTP **та же**, что у kube-api: в Yandex Cloud адрес не может быть в двух группах одновременно. Из этого следует, что проверка доступности одна — TCP на `6443`, про здоровье узла, а не про nginx.

## Что важно знать

- **Порт зашит в двух местах.** `nodePort: 30080` здесь и `http_node_port = 30080` в `infra/yc/terraform/cluster/main.tf`. Менять только вместе, иначе балансировщик будет слать в пустоту.
- **Почему не Ingress.** На кластере `yc` нет ingress-контроллера, а NLB — L4. Ingress появится вместе с ingress-контроллером и своим Service; этот юнит тогда удаляется.
- **Только HTTP.** Ни TLS, ни виртуальных хостов, ни маршрутизации по путям: один сервис на один порт.
- **Наружу открыт NodePort.** В группе безопасности кластера есть правило на 30080 из интернета — это следствие того, что NLB сохраняет адрес клиента. Если тестовая страница больше не нужна, правило уходит вместе с юнитом.
- **Namespace не удаляется автоматически** (`prune: disabled`): снятие манифеста уносит Deployment и Service, но не namespace с его содержимым. Убирать руками.
- **Образ unprivileged**: работает под UID 101, слушает 8080, root в контейнере не нужен.

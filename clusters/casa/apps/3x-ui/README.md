# 3x-ui

3x-ui — веб-панель для управления Xray-core. Она создаёт inbound-подключения,
клиентов и подписки, считает трафик, задаёт лимиты и сроки действия, показывает
активные подключения и экспортирует готовые клиентские конфигурации. Поддерживает
VLESS, VMess, Trojan, Shadowsocks, WireGuard, Hysteria2, HTTP/SOCKS и несколько
транспортов, включая TCP, WebSocket, gRPC и XHTTP.

Проект предназначен авторами для личного использования. Панель получает полный
контроль над прокси-конфигурацией, поэтому её нельзя публиковать напрямую в
интернет. В этом репозитории интерфейс доступен только через локальный Traefik,
а Xray получает один заранее опубликованный порт `8443` по TCP и UDP.

Панель читает `homelab-config` (`TZ`) из своего namespace — ConfigMap создаёт
платформенный чарт, чарт 3x-ui от него зависит и сам его не создаёт.

## Egress-прокси (порт 8440)

На порту `XUI_EGRESS_PORT` (по умолчанию `8440`) работает HTTP forward proxy.
Внутри Xray пересылает трафик через VLESS-подключение на внешний сервер в
другой стране. Из кластера прокси доступен по внутреннему DNS-имени
`xui-egress.3x-ui.svc.cluster.local`.

Порт открыт только для namespace `monitoring` (`NetworkPolicy` `allow-ingress`).
С узла путь работает, потому что сервис объявлен с `externalIPs`; из LAN и из
tailnet порт закрыт политикой.

Gatus использует этот прокси для:

- Доставки Telegram-уведомлений (Telegram заблокирован в России).
- Мониторинга доступности самого прокси: HTTP-запрос к `api.telegram.org`
  через `client.proxy-url` показывает реальную задержку маршрута.

## Аутентификация прокси

Прокси работает в режиме `auth: password`. Учётная запись одна на потребителя,
поэтому у каждого своя: сейчас их две — `gatus` и `dns01-webhook`. Записи живут в
базе панели: панель не читает их из окружения, поэтому заводятся в UI вручную.

Почему по записи на потребителя, а не одна общая: пароль можно отозвать,
не ломая соседей, и ротация одного не трогает остальных
(`docs/adr/0006-vault-secret-path-layout.md`).

Значение хранится в Vault по пути `kv/3x-ui/@gatus/egress` с ключами
`XUI_EGRESS_USERNAME` и `XUI_EGRESS_PASSWORD` и доставляется в namespace
`monitoring` как Secret `xui-egress`. Сегмент `@gatus` — потому что кред
выдан отдельному потребителю и должен отзываться независимо от секретов 3x-ui
(`docs/adr/0006-vault-secret-path-layout.md`).

База панели уже содержит запись, созданную при `auth: noauth`. Переключать
auth на неё нельзя: её пароль скомпрометирован, нужна новая пара.

Реквизиты подставляются в URL прокси, поэтому пароль обязан состоять из букв,
цифр и `-`, `_`, `.`. Символы `@`, `:`, `/`, `#`, `%` и пробелы ломают разбор
URL.

Учётная запись `dns01-webhook` — по пути `kv/3x-ui/@dns01-webhook/egress`,
Secret `dns01-webhook-egress` в namespace `cert-manager`.

Значение существует в двух местах — в базе панели и в Vault, — поэтому ротация
это два шага. Порядок и команды — в `RUNBOOK.md`.

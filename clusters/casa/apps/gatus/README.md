# Gatus

Gatus — основной декларативный монитор доступности homelab.
URL: `https://uptime.example.com/`.

`config/config.yaml` лежит в исходном виде, а `configMapGenerator` собирает из
него ConfigMap `gatus-config` (имя получает hash-суффикс от содержимого) и
монтирует в под как `/config/config.yaml`. Правка конфига меняет pod-template и
сама запускает rollout — отдельный `kubectl rollout restart` не нужен.

## Хранилище

История проверок — PostgreSQL в общем кластере CNPG `shared` (namespace
`databases`, эндпоинт `shared-rw.databases.svc.cluster.local:5432`). Роль
`gatus`, база `gatus` и NetworkPolicy объявлены в `clusters/casa/platform/cnpg/`; пароль роли
приходит в под из Secret'а `gatus` (ключ `GATUS_DB_PASSWORD`) и подставляется в
`storage.path` через `${GATUS_DB_PASSWORD}`.

Бэкапы и ретеншен базы — на стороне CNPG (`clusters/casa/platform/cnpg/README.md`). При
переезде с SQLite история не переносилась: мониторинг начал с чистого листа.

## Уведомления через ntfy

Канал уведомлений — [ntfy.sh](https://ntfy.sh): self-hosted не требуется,
Gatus публикует в публичный топик исходящим HTTP-запросом, а телефон получает
push из интернета.

Чтобы не слать уведомления во время обновлений или обслуживания, можно временно
поднять `failure-threshold` в `config.yaml` или остановить проверки.

## Уведомления через Telegram

Второй канал — Telegram: Gatus отправляет сообщения через бота в группу или
личку.

- Бот создаётся в [@BotFather](https://t.me/BotFather) (`/newbot`); полученный
  токен и ID чата задаются в Vault переменными `TELEGRAM_BOT_TOKEN` и
  `TELEGRAM_CHAT_ID` (путь `kv/gatus/secret`) и подставляются в
  `config/config.yaml` через `${...}`. Значения в Git не попадают.
- ID группы отрицательный (для супергрупп — с префиксом `-100`). Чтобы бот
  видел сообщения группы, в BotFather отключите privacy mode (`/setprivacy` →
  `Disable`); ID группы можно узнать через `https://api.telegram.org/bot<TOKEN>/getUpdates`.
- Пороги те же, что у ntfy: три подряд неудачи и уведомление о восстановлении
  (`alerting.telegram.default-alert`).

## Прокси для внешних проверок

Telegram-уведомления и проверка «Xray proxy egress» ходят в интернет через
forward proxy 3x-ui (`clusters/casa/apps/3x-ui/`). Адрес берётся как внутреннее DNS-имя
сервиса `xui-egress.3x-ui.svc.cluster.local`, реквизиты — из Secret'а
`xui-egress`, который VSO наполняет по пути `kv/3x-ui/@gatus/egress`. Deployment
собирает из них `XUI_EGRESS_PROXY_URL`, и оба потребителя в `config.yaml`
ссылаются на этот URL, поэтому проверка заодно подтверждает доставку
реквизитов.

Пароль попадает в URL, поэтому в Vault он должен быть без `@`, `:`, `/`, `#`,
`%` и пробелов — иначе Gatus не распарсит адрес и уведомления молча пропадут.
Проверка «Xray proxy egress» словит это раньше, чем вы заметите по телефону:
она идёт через тот же прокси, поэтому без рабочих реквизитов она станет DOWN.

## Проверки внешних источников

Группа `External` отвечает на вопрос «сломалось у нас или у сервиса» для
внешних адресов, от которых зависит homelab. Каждый сервис проверяется тремя
эндпоинтами:

- `<сервис> DNS via CoreDNS` — DNS-запрос через кластерный резолвер, то есть тем
  же путём, что ходят поды и job'ы;
- `<сервис> DNS via Technitium` — тот же запрос напрямую в Technitium, минуя
  промежуточный резолвер (роутер в LAN). Если падает первый чек, а второй
  зелёный, виноват промежуточный резолвер, а не Technitium и не сервис;
- `<сервис> upstream` — HTTPS-эндпоинт целиком, то есть DNS+TLS+HTTP.

Проверяются:

- `Actions` — `data.forgejo.org`: раннер тянет оттуда экшены
  (`uses: actions/checkout@v6`), проверяется git-эндпоинт `actions/checkout`
  (корень сайта отдаёт редирект);
- `GitHub` — `github.com` (публичное зеркало и экшены), проверяется
  `robots.txt` (корень — тяжёлая главная);
- `GHCR` — `ghcr.io`, источник job-образов;
- `Docker Hub` — `registry-1.docker.io`, API реестра Docker Hub;
- `Google` (`www.google.com`) и `Yandex` (`ya.ru`) — референсы общего
  доступа в интернет, по ним видно, что «упало» не только у провайдера.

У реестров (`GHCR`, `Docker Hub`) проверяется `/v2/`: без токена он отвечает
`401`, и это же означает, что реестр жив — токен `docker pull` получает
отдельно на `auth.docker.io`.

`interval: 15s` у группы выбран по длительности реальных отказов (~75 с): при
`60s` и `failure-threshold: 3` порог срабатывания — три минуты, и такие окна
проходят незамеченными.

Сам Gatus не способен доставить уведомление о полном падении сервера, на котором
он работает. Для питания, хоста и домашнего подключения нужна дополнительная
проверка извне или со второго устройства.

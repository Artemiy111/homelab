# OpenCost

Считает, во сколько обошёлся кластер, по облачному прайсу. Нужен странице
**Cost Monitoring** в Lens Desktop: без OpenCost Lens умеет только собственный
Estimate, который покрывает CPU и память и берёт ставки из каталога типов нод.
У bare-metal ноды типа нет, поэтому Estimate вырождается в ставки, введённые
руками в интерфейсе, а storage и network остаются нулями.

OpenCost взят вместо Kubecost по двум причинам: Kubecost — это тот же движок
OpenCost плюс коммерческая обвязка, а Lens читает данные обоих одинаково; для
одного узла обвязка не нужна. Исходные цифры облака при этом не читаются: cloud
integration не настроена, а цена берётся из прайс-листа в ConfigMap. То есть
показанное — «прайс-лист × потребление», а не счёт.

## Как считает

Вход — метрики, которые уже собирает vmagent: kubelet и cAdvisor дают
потребление контейнеров, kube-state-metrics — состояние объектов. Все они лежат
в VictoriaMetrics, и OpenCost читает её как источник данных, отдельного
Prometheus не появляется.

Стоимость ноды OpenCost собирает из прайса за vCPU·час и GiB·час, применённого к
capacity ноды, а затем раскладывает её по namespace. Тома считаются по цене за
GiB·час, сеть — по объёму.

Интервал скрейпа задан явно. По умолчанию OpenCost выясняет его у Prometheus
через `/status/config`, а VictoriaMetrics такого эндпоинта не имеет; без явного
значения OpenCost пользовался бы своим дефолтом, не совпадающим с vmagent.

## Прайс

Прайс — ConfigMap с плоскими ключами: OpenCost раскладывает `data` прямо в поля
своей модели цен, поэтому структура вложенной быть не может. В репозитории лежат
два готовых пресета, активный выбирается одним значением в манифесте:

- **aws** — копия `configs/aws.json` из самого OpenCost: ставки за vCPU·час и
  GiB·час, посчитанные по AWS, объём хранилища по $0.04/GiB·месяц, исходящий
  трафик по $0.143/GiB, NAT по $0.045/GiB.
- **yandex** — прайс Yandex Cloud для региона Россия, платформа Intel Ice Lake,
  100% vCPU: цены действуют с 30 апреля 2026. Хранилище — быстрый диск (SSD),
  исходящий трафик — 1.42 ₽/ГБ после бесплатных 100 ГБ в месяц, GPU — Nvidia T4.

Прайс выбран пресетом, а не расчётом из биллинга, потому что биллинга и нет:
платится только электричество. Цифры нужны как ориентир «сколько это стоило бы
в облаке».

## Что осознанно неверно

- **Валюта.** У OpenCost нет поля валюты, и он вместе с Lens рисует `$`. В
  пресете yandex числа рублёвые, поэтому знак валюты в интерфейсе неверен; само
  число при этом — из прайс-листа Yandex Cloud.
- **Спотовые ставки не применяются.** `spotCPU` и `spotRAM` в пресетах есть, но
  OpenCost считает ноду спотовой только по метке, названной в `spotLabel`, — а
  она не задана. Пока не задана, спотовые ставки не влияют ни на что.
- **Скидки и резервы.** Ни negotiated discount, ни CVoS, ни Savings Plans не
  учитываются: этого в модели нет.
- **Нулевые ставки у Yandex.** У Yandex нет NAT gateway, а трафик между сервисами
  облака по внутренним адресам не тарифицируется, поэтому в пресете yandex
  нулевые ставки NAT и межзонального трафика. Это не пропуск, а прайс.

## Чего у него нет

- **UI.** Потребитель — Lens, он читает API OpenCost напрямую. Отдельный
  интерфейс не поднимается, чтобы не держать второй вход в кластер.
- **Персистентности.** Всё, что OpenCost считает, он берёт из VictoriaMetrics;
  своих данных, которые надо было бы хранить, у него нет.
- **Мультикластерности.** Кластер один, и `CLUSTER_ID` нужен только чтобы
  кластер был подписан в ответах API.

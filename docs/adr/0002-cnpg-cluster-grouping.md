# Кластер CNPG — единица общей судьбы, а не единица сервиса

Держим несколько баз в одном CNPG-кластере **по умолчанию**, а отдельный
заводим только под форсирующую причину: мажор версии, расширения, blast
radius, профиль нагрузки, политика бэкапа и окно обслуживания. Число кластеров
равно числу единиц общей судьбы, а не числу сервисов. Логическая изоляция
(база и роль на сервис, `CONNECTION LIMIT`, пер-ролевые
`statement_timeout`/`work_mem`) даёт то, ради чего иначе городили бы кластер на
каждый сервис.

## Considered Options

- **Кластер на сервис** — каждый CNPG-кластер это два контейнера на
  инстанс (postgres + instance manager), свой `shared_buffers`, свой WAL, свой
  PVC, своя конфигурация бэкапа и своё окно апгрейда. Для баз в десятки
  мегабайт это десятки postgres-процессов, которые надо патчить, бэкапить и
  апгрейдить по отдельности.
- **Общий кластер** — прод-практика: никто не поднимает по инстансу RDS на
  микросервис. Цена — общий `shared_buffers` и один primary, поэтому тихие базы
  группируются, тяжёлые — нет.

## Consequences

- `shared` (`databases`): nextcloud, forgejo, synapse, paperless, glitchtip,
  playground, authentik (тестовый стенд). Расширений нет, PG18.
- `zitadel` — отдельный по blast radius: падение IdP роняет всё, что логинится.
- `immich` — **вынужденно** отдельный: VectorChord требует
  `shared_preload_libraries`, а это параметр кластера, поэтому библиотека
  грузится во всех его базах. «Кому надо — использует» здесь не работает, в
  отличие от per-database расширений.
- `dawarich` — отдельный по выгоде: PostGIS через Image Volume Extensions
  ставится per-database, но обновление extension-образа перекатывает весь
  кластер, а мажорный апгрейд ждёт сборки PostGIS под новый PG.
- Тестовый стенд authentik садится на `shared_buffers` вместе с боевыми базами.
  Принято сознательно, потому что стенд снимается; при снятии удаляются и
  `Database`, и роль.
- Сервисы ставятся Helm-чартами, у которых **выключается встроенная база** и
  указывается внешний хост. Иначе консолидация отменяется и чарты поднимают по
  случайному Postgres'у.

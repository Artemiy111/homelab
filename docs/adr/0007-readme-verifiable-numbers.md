# README показывает проверяемые числа, а не статусы сервисов

В README нет бейджей «живо/не живо» по каждому сервису. Вместо них — несколько
чисел о самом репозитории: сервисы, манифесты, доля образов, закреплённых по
digest, namespace'ы под NetworkPolicy, ADR, постмортемы. Числа считает
`scripts/status-badges.sh` из содержимого git, артефакты (`docs/status/`)
лежат в коммите, а CI-гейт падает, если они разошлись с репозиторием.

## Considered Options

- **Бейджи Gatus через shields.io** — Gatus сам умеет отдавать SVG и
  shields-совместимый JSON по `/api/v1/.../badge.svg`, и данные были бы живые.
  Не подходит: ссылка на бейдж — это ссылка на сервис, то есть внутренний
  адрес, который нельзя выносить в публичное зеркало
  (`docs/agents/information-handling.md`). Второй вариант того же — публичный
  ingress только под бейджи: он раскрывает домен и оставляет наружу API
  мониторинга, а это новая поверхность атаки ценой одного бейджа.
- **Uptime Kuma** — та же проблема плюс состояние хранится в своей БД, а
  история всё равно недоступна читателю.
- **Запекать бейджи по крону** (раз в сутки или чаще) — адреса не утекают, но
  появляются ежедневные коммиты в `main`, нужны бот-токен в кластере и egress к
  forge, а главное — бейдж застывает зелёным, когда упал сам источник данных.
  Отдельный репозиторий под бейджи снимает шум, но не staleness.
- **Считать числа из репозитория** — выбрано. Данные лежат в git, обновляются
  вместе с кодом, устареть не могут, и читатель может открыть скрипт и
  пересчитать.

## Consequences

- **Артефакт в коммите, а не живой бейдж.** Пока нет публичного зеркала на
  GitHub, это единственный способ показать бейдж в README без домена. Когда
  зеркало появится, те же значения уходят в shields через `dynamic/json` с
  `url` на `status.json`; расчёты не меняются, меняется только доставка.
- **Гейт на каждом изменении манифестов.** Любой PR, который добавляет сервис
  или образ, обязан перегенерировать `docs/status/`. Локально это ловит
  `.githooks/pre-commit`, в CI — `status.yml`.
- **Числа детерминированы.** Скрипт не ходит в сеть, не читает время и не
  спрашивает кластер: дата генерации и sha коммита в `status.json` не попадают,
  иначе `git diff` после перегенерации расходился бы на каждом коммите.
- **Тулчейн CI не расширяется.** Генератор на `git`/`grep`/`awk`/coreutils,
  ничего нового в `apps/rustfs/artifacts.tsv` не добавляется.
- **Новый верхний слой `scripts/`.** Репозиторий разложен по роли (`docs/adr/0004`),
  инструментария репозитория раньше не было, и `docs/` для неё не место.
- **Число — нижняя оценка.** Источник только репозиторий, поэтому расхождение с
  живым кластером возможно и не считается ошибкой; исключения перечислены в
  `docs/status/README.md`.
- **Доступность в README пока не показана.** SLO, error budget и MTTR требуют
  истории из Gatus, а не из git. Это отдельная задача и отдельный формат; запись
  «No SLOs» в `Known limitations` остаётся, пока SLI не появится.

# Инструмент IaC — terraform, запуск с macOS

Инструмент — `terraform` из HashiCorp, не OpenTofu. Конфигурация, state и
запуск живут на macOS; на сервере terraform не устанавливается.

Заменяет `docs/adr/0007-tofu-terraform-compatibility.md`.

## Почему terraform, а не OpenTofu

Выбор OpenTofu был вынужденным: пакета `terraform` нет в репозиториях Fedora, а
`releases.hashicorp.com` и `registry.terraform.io` гео-блокируются. С тех пор
`terraform` 1.16.4 стоит на macOS, а VPN открывает и релизы, и реестр —
исходное ограничение снято, и основание выбирать форк исчезло. Правило 0007
«только то, что понимает terraform» превращается из ограничения в требование к
самому себе: одинаковое поведение без обходных путей.

Отдельно: `terraform` начиная с 1.6 лицензирован BSL. Для личного и внутреннего
использования это не ограничение; оно появилось бы, только если бы код
предлагался как сервис.

## Почему запуск с macOS, а не с сервера

- Ни один слой доставки terraform не вызывает: хостом управляет Ansible,
  кластером — ArgoCD. Это ручной CLI, и место его запуска не навязано
  архитектурой.
- State и токены остаются на машине, где пересборка сервера их не сольёт, и где
  `plan` можно прочитать глазами перед `apply`. Автономный apply с сервера на
  внешнюю DNS-зону — изменение без присмотра; технически возможно, но должно
  быть решено, а не подразумеваться.
- Восстановление после потери сервера работает именно потому, что Mac от него
  не зависит.

## Что изменится, если появится работа по расписанию

Задачи, которые должны выполняться без участия человека — ноутбук выключен,
спит, VPN отвалился — с Mac не выполняются: обновление DNS-записи по расписанию,
выпуск сертификата через DNS-01, сверка внешнего состояния с кластером.

Место раннера тогда — кластер, а не хост:

- у Job в кластере есть service account, поэтому Vault и Technitium доступны
  нативно: без Tailscale, без публикации маршрутов и без хранения кластерных
  токенов на ноутбуке;
- расписание в кластере уже есть (`mirror-sync`, `apps/rustfs`);
- тот же сценарий на хосте потребовал бы отдельного systemd-таймера, отдельных
  прав и ручной пробраски токенов внутрь — то есть больше движущихся частей
  при том же результате.

Цена: раннер в кластере не достаёт до реестра провайдеров, потому что egress
кластера равен egress сервера. Провайдеры придётся вендорить в образ или
поднимать зеркало реестра. Это отдельное решение с отдельными последствиями, а
не следствие настоящего ADR.

## Considered Options

- **Оставить OpenTofu** — отклонено: ограничение снято, а преимущество
  (нативное шифрование state) всё равно недоступно, раз 0007 его запрещал.
  Держать форк только ради факта установки — цена без выигрыша.
- **Поставить terraform и на сервер, а state держать на Mac** — отклонено:
  расхождение между местом state и местом запуска означает перенос state по
  сети при каждом прогоне, при этом не добавляет ничего.
- **Оставить opentofu на сервере как резерв на случай блокировки** —
  отклонено: инструмент, которым не управляет ни одна конфигурация, не
  является резервным путём, а два инструмента в одном репозитории — это два
  источника истины вместо одного.
- **Отдельный репозиторий под IaC-конфигурацию** — отклонено: у нас один
  контекст, и отдельный репозиторий ради одного слоя усложнит доставку без
  выигрыша.

## Consequences

- `opentofu` убран из `base_packages`: в репозитории не остаётся инструмента,
  которым ничего не управляется. Физически пакет на сервере снимается
  вручную (`dnf remove opentofu`) — Ansible пакеты вне списка не удаляет.
- На каждом `init`/`plan` с провайдерами нужен доступ к реестру HashiCorp, то
  есть `HTTPS_PROXY` в окружении macOS. VPN у macOS настроен системным
  прокси, который CLI не читает, поэтому переменная экспортируется явно.
- Пакет `terraform` на сервере не появится и не нужен: ничто в доставке его не
  вызывает, а автономный запуск переезжает в кластер, а не на хост.

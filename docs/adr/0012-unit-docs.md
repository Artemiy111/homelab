# Юнит-док: README описывает сервис, RUNBOOK рядом с ним — эксплуатацию

Заменяет ту часть [0011](0011-repository-layout-v2.md), по которой
`argocd/README.md` уехал в `docs/runbooks/`.

Отделять описание от процедур нужно, но каталог для этого не обязателен: имя
файла различает не хуже. `README.md` юнита описывает сам сервис, `RUNBOOK.md`
рядом с ним — то, что делают руками; `docs/runbooks/` остаётся для сквозных тем,
не принадлежащих одному юниту. Правило содержимого — `docs/agents/unit-docs.md`.

## Почему

- **Разные ситуации чтения.** README открывают, чтобы понять сервис, RUNBOOK —
  чтобы что-то с ним сделать. В одном файле процедура вытесняет описание:
  README на 600 строк читается как журнал разборов.
- **Разные каталоги разъезжаются.** Процедура в `docs/runbooks/` и README в
  юните описывали один сервис врозь (`longhorn`), а правка процедуры требовала
  помнить, что она лежит в другом дереве.
- **Имя вместо каталога.** В 0011 разделение делал каталог, потому что имя было
  одно. Появилось второе имя — каталог перестал быть нужен, а локальность
  вернулась: всё о юните лежит рядом с его манифестами.

## Следствия

- `docs/runbooks/argocd.md` и `docs/runbooks/longhorn.md` возвращаются в свои
  юниты как `RUNBOOK.md`; `docs/runbooks/` остаётся пустым каталогом с
  указателем, чтобы процедуры юнитов не завелись там снова.
- `README.md` юнита больше не содержит путей к своим манифестам, перечисления
  файлов каталога и команд: всё это либо видно из дерева, либо уезжает в
  RUNBOOK.
- ADR и постмортемы остаются записями о моменте времени — пути в них не
  обновляются вместе с переименованиями.

# prune включён у юнитов, невосстановимые ресурсы защищены аннотацией

Заменяет ту часть решения #931, по которой prune выключен у владельцев
namespace'ов, и вывод RUNBOOK Argo «против prune сирот нужен запрет самого
`prune`».

Prune у приложения юнита включён, а ресурсы, потеря которых необратима — PVC и
namespace, — снимают его точечно аннотацией:

```yaml
metadata:
  annotations:
    argocd.argoproj.io/sync-options: Prune=false
```

## Почему

- **Выключенный у приложения prune — защита не того размера.** Он щадит весь юнит
  целиком, а терять нельзя только часть. Плата — обратная сторона: ресурс,
  пропавший из git, не удаляется и ждёт; приложение уходит в `OutOfSync`, и
  сигнал перестаёт что-либо значить. Так и вышло с `configMapGenerator`: имя
  ConfigMap содержит хеш содержимого, поэтому каждая правка конфига оставляла в
  кластере прежний объект, а приложение показывало `OutOfSync` до ручного
  удаления. Хуже — если объект применён не Argo, его нет и в diff: у `verdaccio`
  такой остаток лежал молча.
- **PVC не восстанавливается из git.** Данные тома git не содержит, и судьбу
  их решает `reclaimPolicy` класса: у `longhorn-retain` после удаления PVC
  остаётся осиротевший том (восстановление руками, `RUNBOOK.md` longhorn), а у
  `longhorn` том и данные уходят вместе с PVC. Это единственное удаление,
  которое Argo не может отменить.
- **Namespace уносит с собой всё, чего нет в git.** Инцидент
  [0009](../incidents/0009-applications-and-namespaces-recreated.md): 13
  namespace'ов вернулись сами, а `uptime-kuma` нет — его MariaDB применяется
  руками, CR исчез вместе с namespace, PVC вместе с ним, сервис стоял 15,5 часов.
  Опечатка в имени namespace не должна стирать содержимое автоматически.
- **Стабильное имя ConfigMap без хеша — не выход.** Kubelet обновляет
  смонтированный ConfigMap на месте (замер: правка видна в поде через ~1,5
  минуты, рестарт не нужен), но процесс читает конфиг при старте: файл станет
  новым, поведение — старым, и это расхождение git с реальностью не видно ни в
  `Synced`, ни в diff. При `subPath` не обновляется и файл (`structurizr`,
  `element`, `paperless`). Хеш в имени как раз и перезапускает под сам — поэтому
  он остаётся, а прежний ConfigMap теперь удаляет prune.

## Следствия

- Удаление ресурса из git удаляет его в кластере — это и есть обещание GitOps.
  Исключение — защищённые PVC и namespace.
- Защищённые PVC и namespace удаляются только руками. Namespace, убранный из
  git, остаётся сиротой вместе с содержимым: если удаление задумано, его делают
  `kubectl delete`.
- Платформенные компоненты политика не касается: они ставят операторов, и там
  prune выключен осознанно — кластерные CRD из git не удаляются
  (app-level `Prune=false` в `clusters/casa/platform/*/app.yaml`). Юниты без
  автоматической синхронизации (`alloy`, `alloy-profiler`, `authentik`, `beyla`,
  `gitlab`, `local-ai`) тоже вне политики: у них синка нет вовсе.
- Соответствие держит гейт `scripts/argocd-prune.sh --check` — в `pre-commit`,
  в `scripts/check.sh` и в workflow `gitops.yml`. Он проверяет три вещи:
  приложение юнита с `automated` несёт `prune: true`, каждый PVC и namespace —
  аннотацию, а root не глушит политику синка `ignoreDifferences`. Без гейта
  политика расходится молча: новый юнит копирует соседний манифест, и разница
  видна только тем, что Argo удалит ресурс, которого нет в git.
- Политика синка принадлежит git целиком. У root стояло `ignoreDifferences` на
  `/spec/syncPolicy/automated`, и `prune` из `app.yaml` не доезжал до кластера —
  правка была вхолостую. Правило снято (вместе с мёртвым правилом для
  `ApplicationSet`: `ApplicationSet` в репозитории нет). У root при этом нет
  `selfHeal`, поэтому ручное отключение автосинка переживёт до следующей
  синхронизации root, а не станет вечным.

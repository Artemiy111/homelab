## Self-Hosted решения для видеоконференций

### Jitsi Meet ⭐ (Текущий)

| | |
|---|---|
| Сайт | https://jitsi.org/ |
| GitHub | https://github.com/jitsi/jitsi-meet (~30k ⭐) |
| Лицензия | Apache-2.0 |
| Docker | ✅ |
| Архитектура | SFU (Selective Forwarding Unit) |

Самая популярная open-source платформа видеоконференций. На базе WebRTC, не требует аккаунта для публичных инстансов. Поддерживает до 1080p, демонстрация экрана, чат, breakout-комнаты, E2EE (для 1:1), запись через Jibri (headless Chrome). JWT-авторизация, LDAP, SAML. Мобильные приложения (iOS/Android).

**Требования к ресурсам:**

| Параметр | Значение |
|---|---|
| Мин. RAM | 2 GB (тест), 4 GB (маленький сервер), 8 GB (рекомендуется) |
| Мин. CPU | 2 выделенных ядра (4 рекомендуется) |
| Мин. диск | 20 GB |
| Пропускная способность на видеопоток | 200 Kbps (180p) — 2.5 Mbps (720p) — 10 Mbps (4K) |
| Jibri (запись) | 8 GB RAM на одну сессию записи |
| Макс. участников (один узел, SFU) | 35–75 с видео, 500+ только аудио |

**Качество:** До 1080p (720p типично для групповых звонков). Модель SFU означает отсутствие транскодирования на сервере — качество зависит от пропускной способности клиента. Адаптивный битрейт. Отлично для 2–35 участников.

**Плюсы:** Самое зрелое и широко развёрнутое решение. Огромное сообщество. Простая установка через Docker. Встраивание через iFrame API. E2EE. Не нужен аккаунт на публичном инстансе.

**Минусы:** Запись (Jibri) очень ресурсоёмкая (headless Chrome на каждую запись). Минимум 4 сервиса (web, prosody, jicofo, JVB). Масштабирование требует кластеризацию Octo. Только community-поддержка для self-hosted.

**Статус:** Очень активный. Последний стабильный релиз 11031 (июнь 2026). 749 коммитов за последний год.

### BigBlueButton

| | |
|---|---|

| Лицензия | LGPL-3.0 |

**Требования к ресурсам:**

| Параметр | Значение |
|---|---|
| Мин. RAM | 4 GB (Docker), 16 GB (рекомендуется для прода) |
| Мин. CPU | 4 ядра (8 рекомендуется для прода) |
| Мин. диск | 50 GB (без записи), 500 GB (с записью) |

| Макс. участников | 100–200 одновременных на 16 vCPU/32 GB |

**Плюсы:** Лучший для образования (доска, опросы, breakout-комнаты). Встроенная запись. Интеграция с LMS. Панель Greenlight. Проверен в университетах по всему миру.

**Минусы:** Тяжёлые требования к ресурсам. Сложная установка. Docker-деплой имеет ограничения (без поддержки NAT, нужен host-networking). Нет мобильных приложений (только веб). Избыточно для простых командных звонков.

**Статус:** Очень активный. v4.0.0-beta.4 (август 2026). 2k коммитов за последний год.

### MiroTalk P2P

| | |
|---|---|
| Сайт | https://p2p.mirotalk.com |
| GitHub | https://github.com/miroslavpejic85/mirotalk (~4.7k ⭐) |
| Лицензия | AGPL-3.0 |
| Docker | ✅ (`mirotalk/p2p`) |
| Архитектура | P2P (WebRTC) |

Легковесное P2P-видеоконференции в одном контейнере. До 8K при 60fps (теоретически, зависит от клиента). Интерактивная доска, обмен файлами, интеграция ChatGPT, распознавание речи, демонстрация экрана, запись. 133 языка. REST API. OIDC-авторизация.

**Требования к ресурсам:**

| Параметр | Значение |
|---|---|
| Мин. RAM | ~256 MB (только сигнальный сервер) |
| Мин. CPU | 1 vCPU достаточно для сигналинга |
| Мин. диск | ~120 MB (Docker-образ) |
| Пропускная способность | От клиента к клиенту, сервер обрабатывает только сигналинг |
| Макс. участников | Практически 4–10 (ограничение P2P-месха) |

**Качество:** До 4K/60fps для звонков 1:1. Качество деградирует с ростом числа участников (P2P-меш). Рекомендуется TURN-сервер для NAT traversal.

**Плюсы:** Чрезвычайно лёгкий. Один контейнер. Набор функций (доска, AI, запись). Не нужна БД. Полная поддержка ребрендинга. Очень простой деплой.

**Минусы:** P2P-меш — нет серверного SFU, масштабирование ограничено. Нет постоянных комнат или истории чата. Нет мобильных приложений (только браузер). Лицензия AGPL.

**Статус:** Активный. 2 535 коммитов. 453 коммита за последний год.

### LiveKit + Meet

| | |
|---|---|
| Сайт | https://livekit.io / https://github.com/suitenumerique/meet |
| GitHub | https://github.com/livekit/livekit (~23k ⭐) |
| Лицензия | Apache-2.0 |
| Docker | ✅ |
| Архитектура | SFU |

LiveKit — платформа WebRTC SFU. "Meet" (от La Suite numérique / французское правительство) — полноценное приложение видеоконференций на базе LiveKit. Поддерживает 100+ участников, демонстрация экрана, чат, запись, транскрипция.

**Требования к ресурсам:**

| Параметр | Значение |
|---|---|
| Мин. RAM | ~512 MB (только сервер LiveKit) |
| Рекомендуемая RAM | 16 GB (для ~200 одновременных пользователей) |
| Мин. CPU | 2 ядра (маленький сервер), 4+ ядра (прод) |
| Пропускная способность | SFU-переадресация, масштабируется с участниками |
| Redis | Нужен для кластеризации multi-node |
| Макс. участников | 100+ на комнату, 200+ одновременных на одном узле |

**Качество:** Отличное. Современный SFU. Адаптивный битрейт. Низкая задержка. Поддержка E2EE. Используется французским правительством (платформа Visio).

**Плюсы:** Продакшен-уровень SFU. Отличное масштабирование. E2EE. Кластеризация через Redis. Активная разработка. Поддерживается государством (Meet). Запись через сервис Egress.

**Минусы:** Более сложный деплой (сервер LiveKit + Redis + TURN + Egress для записи). Требует host-networking. TURN-сервер обязателен (20–40% соединений его требуют). Приложение Meet относительно новое.

**Статус:** Очень активный. 23k звёзд. LiveKit Cloud доступен как управляемая альтернатива.

### Element Call (Matrix)

| | |
|---|---|
| Сайт | https://element.io |
| GitHub | https://github.com/element-hq/element-web (~13.2k ⭐) |
| Лицензия | AGPL-3.0 |
| Архитектура | P2P / LiveKit (MatrixRTC) |

Element (клиент Matrix) имеет нативные видеозвонки через Element Call (на базе LiveKit, протокол MatrixRTC) или устаревшую интеграцию через виджет Jitsi. E2EE по умолчанию. Звонки 1:1 — P2P через Matrix.

**Качество видео:**
- **Элемент 1:1 (P2P)** — теоретически до 4K (WebRTC), но по умолчанию 720p; настраивается через код/флаги
- **Element Call (LiveKit)** — по умолчанию 720p; поддерживает 1080p+ через конфигурацию LiveKit (`max_bitrate`, `max_bitrate_per_participant`). Требует настройки `config.yaml` LiveKit с увеличением лимитов
- **Проблема:** Element не документирует настройку качества видео; по умолчанию 720p. Чтобы получить 1080p+, нужно вручную редактировать конфигурацию LiveKit и potentially Element's `callMaxBitrate`
- **В реальности:** Качество «заметно грубее», чем у Discord/Zoom; оптимизировано для стабильности, а не для максимального разрешения

**Требования к ресурсам:**

| Параметр | Значение |
|---|---|
| Стек | Synapse homeserver + Element Web + LiveKit + TURN |
| Мин. RAM | 1 GB (Synapse) + 2 GB (LiveKit) = **~3 GB** |
| Рекомендуемая RAM | 4–8 GB (Synapse 2–4 GB + LiveKit 2–4 GB) |
| Мин. CPU | 2 ядра (Synapse) + 2 ядра (LiveKit) = **4 ядра** |
| Рекомендуемый CPU | 4–8 ядер |
| Мин. диск | 50 GB (Synapse БД + логи) |
| Пропускная способность | SFU-переадресация через LiveKit |
| Порты | 8480/tcp (Synapse), 7880/tcp (LiveKit), 7881/tcp (LiveKitRTC), 50000–60000/udp (WebRTC) |

**Плюсы:** Полноценная платформа мессенджера со встроенными звонками. E2EE. Федиляция. Бриджинг к другим платформам. Element Call — современный (на базе LiveKit).

**Минусы:** Сложный стек (3–4 сервиса). Качество видео по умолчанию 720p (нужна ручная настройка для 1080p). Требует эксплуатации Synapse (тяжёлый) + LiveKit. Интеграция Jitsi устарела. Push-уведомления требуют настройки Sygnal/CallKit.

**Статус:** Активная разработка. Synapse требует PostgreSQL для прода (не SQLite).

## Живой стриминг с дронов DJI (текущая настройка)

Дроны DJI (серии Mavic, Mini, Inspire с контроллерами RC Pro/RC Plus) поддерживают live-стриминг через:

| Метод | Протокол | Задержка | Примечания |
|---|---|---|---|
| DJI Fly App (RTMP) | RTMP | 3–8с | Напрямую на YouTube/Facebook/кастомный RTMP |
| DJI RC Pro (RTMP) | RTMP | 3–8с | Встроенный стриминг на контроллере |
| DJI FlightHub 2 | Проприетарный | ~2с | Enterprise-платформа, облако |
| Кастомный WebRTC (android-webrtc-dji) | WebRTC | <1с | DIY, суб-секундная задержка |
| EyesOn (коммерческий) | RTMP → WebRTC | ~200мс | Self-hosted, $39/мес + настройка |
| Larix Screencaster | RTMP/SRT | 1–3с | Android-приложение на DJI RC Plus |

**Качество:** Зависит от модели дрона и системы передачи (O3+, O4, Lightbridge). Обычно 1080p при 30fps для live-стрима. Запись 4K.

**Важные моменты по текущему стеку:**
- Стриминг DJI — **односторонний** (дрон → зритель), не двунаправленный видеозвонок
- Если нужна двунаправленная связь (пилот + наземная команда), комбинировать с Jitsi/MiroTalk
- RTMP-ингест в SRS (Open Source Streaming Server) или OBS для ретрансляции
- Суб-секундная задержка WebRTC возможна с кастомными решениями

## Мессенджеры с видеозвонками

Решения, объединяющие функции мессенджера (чат, контакты, уведомления) и видеозвонков. Ближе всего к UX WhatsApp/Telegram.

### Jami ⭐ (Лучший для 1:1 звонков)

| | |
|---|---|
| Сайт | https://jami.net/ |
| GitHub | https://git.jami.net/jami-project/jami-client-desktop |
| Лицензия | GNU GPLv3+ |
| Docker | ✅ (серверная часть) |
| Архитектура | P2P (через DHT) |

Дистрибутивная платформа для мгновенных сообщений, голосовых и видеозвонков. Полностью P2P — нет центрального сервера. Работает через DHT-сеть (как BitTorrent). Учётная запись — X.509 сертификат, генерируемый локально. Не нужен телефон или email для регистрации.

**Платформы:** Linux, Windows, macOS, Android, Android TV, iOS, iPadOS, веб-интерфейс (ограниченный)

**Качество видео:** До 4K с аппаратным ускорением (H264, VP8). Адаптивный битрейт. Используйте SIP для подключения к обычным телефонам.

**Особенности:**
- Прямой звонок из контактов (как WhatsApp)
- Push-уведомления на мобильных устройствах
- Групповые звонки и видеоконференции
- Обмен файлами без ограничений
- Работа в LAN без интернета (Rendezvous mode)
- Расширения (зелёный экран, фильтры)
- SIP-клиент (можно звонить на обычные телефоны)
- Запись звонков (только десктоп)

**Требования к ресурсам:** Минимальные. P2P означает, что ресурсоёмкость зависит от числа участников.

**Плюсы:** Полная приватность (нет сервера), E2EE по умолчанию, все платформы, работает офлайн в LAN, не нужен аккаунт.

**Минусы:** UI может казаться устаревшим, качество видео зависит от P2P соединения (NAT traversal может не работать), стабильность групповых звонков ниже, чем у SFU-решений.

**Статус:** Активный. GNU project, развивается Savoir-faire Linux + сообщество.

## Справочник по пропускной способности и качеству

| Разрешение | Битрейт на поток | Сценарий использования |
|---|---|---|
| 180p | 200 Kbps | Резервный аудио-режим, мобильные на медленных сетях |
| 360p | 500 Kbps | Видео с низкой пропускной способностью |
| 720p (HD) | 2.5 Mbps | Стандартное качество группового звонка |
| 1080p | 4–5 Mbps | Качественное 1:1 или малая группа |
| 4K | 10 Mbps | Высококачественные звонки 1:1 |

**Формула масштабирования P2P-месха:** Каждый участник отправляет (n-1) потоков. Звонок на 5 человек = 4 потока на человека × 1 Mbps = 4 Mbps аплоада на участника.

**Масштабирование SFU:** Каждый участник отправляет 1 поток на сервер, сервер пересылает (n-1) участникам. Пропускная способность сервера = n × битрейт_потока.

# Числа о репозитории

README показывает не статусы сервисов, а **числа, которые репозиторий знает о
себе**: сколько сервисов, сколько образов закреплено по digest, сколько
namespace'ов закрыто NetworkPolicy. Все они считаются из содержимого git и
проверяются гейтом, поэтому цифру в README можно пересчитать и поспорить с ней.

- `status.json` — те же числа машиночитаемо, единственный источник значения;
- `badges/en/`, `badges/ru/` — SVG-бейджи, на которые ссылаются `README.md` и
  `README.ru.md` относительными путями;
- генератор — [`scripts/status-badges.sh`](../../scripts/status-badges.sh).

## Почему здесь нет аптайма

Бейдж «живо ли сейчас» бесполезен без ссылки на сервис, а ссылка — это внутренний
адрес, который нельзя отдавать в публичное зеркало. Вторая проблема: бейдж,
обновляемый по расписанию, застывает зелёным, когда упал сам источник данных, —
то есть врёт именно тогда, когда важен. Числа из репозитория этой ловушки не
имеют: они меняются вместе с кодом и устареть не могут.

Доступность, SLI/SLO и MTTR в README появятся позже и в другом виде: историю
нельзя вывести из git, она живёт в Gatus и Postgres. Формат — отдельная задача.

## Как считается

| Число | Метод | Границы |
|---|---|---|
| services | каталоги под `apps/`, где есть хотя бы один YAML | включает `apps/elk`, выведенный из эксплуатации: манифесты ещё не удалены |
| manifests | файлы в области гейта kubeconform: `apps/<сервис>/k8s/`, `platform/`, `argocd/` без `values.yaml`, `Chart.yaml` и шаблонов чарта | ровно то, что проверяет CI |
| images pinned | `image: <ref>` одной строкой; в знаменателе только формы, где значение стоит на той же строке | многострочные формы (`image:` + `repository`/`tag` в CNPG и чартах Argo) не считаются: их нельзя объявить незакреплёнными без разбора YAML |
| netpol coverage | namespace'ы, в которых есть манифест с `kind: NetworkPolicy`, делённые на все namespace'ы из `metadata.namespace` | namespace'и читаются по отступу в два пробела (формат kubiform), вложенные `namespace:` из subject'ов RBAC и service-ссылок вебхуков не считаются |
| ADR / postmortems | количество файлов в `docs/adr/` и `docs/incidents/NNNN-*.md` | — |

Число считается по **области, известной только репозиторию**. Namespace или
образ, который есть в живом кластере, но не в манифестах, в знаменатель не
попадёт: это делает число нижней оценкой, а не истиной в последней инстанции.

## Исключения

Список исключений пересчитывается генератором и лежит в `status.json`, здесь —
разбор каждого.

- **Образ без digest** — `apps/structurizr`. Официального образа в registry нет,
  сервис собирается из исходников, тег `localhost/structurizr:<версия>`
  импортируется в containerd узла. Исключение закрываемо: у импортированного
  образа есть digest, его можно указать в `image`; альтернатива — публикация
  сборки в Zot.
- **Namespace без NetworkPolicy:**
  - `traefik`, `cert-manager`, `argocd` — control plane. Причина исключения в
    репозитории не зафиксирована: для `traefik` и `cert-manager` ограничение
    идёт через правила самого Traefik и через NetworkPolicy на webhook
    (`security.networking.k8s.io/v1`), но решение «NetworkPolicy здесь не нужен»
    нигде не записано. Это кандидат на ADR, а не на молчание в документации;
  - `headlamp` — разворачивается Argo, NetworkPolicy нет. Закрывается тривиально,
    ждёт своего issue;
  - `gitlab` — тестовый стенд, применяется вручную, вне Argo.
- **Services** — `apps/elk` заменён на Loki и Alloy, манифесты остались в
  репозитории. Удаление — отдельная задача.

## Перегенерация

```sh
./scripts/status-badges.sh          # пересчитать и записать артефакты
./scripts/status-badges.sh --check  # только проверить, что артефакты свежие
```

Гейт `.forgejo/workflows/status.yml` запускает `--check` на всех изменениях в
`apps/`, `platform/`, `argocd/` и `docs/`: если числа в репозитории разошлись с
артефактами, CI падает с указанием команды. Локально та же проверка висит в
`.husky/pre-commit` — расхождение ловится до коммита, а не после merge.

Скрипт использует только `git`, `grep`, `awk` и coreutils, поэтому новых бинарей
в тулчейне CI не появляется: набор инструментов в
[`apps/rustfs/artifacts.tsv`](../../apps/rustfs/artifacts.tsv) не меняется.

## Гонка при merge

Число зависит от всего дерева, а не от файла, который менял автор. Если пока
твоя ветка ждала review, в `main` влили чужой PR, удаливший манифест, то к
моменту merge твои бейджи уже неверны: гейт на push в `main` это покажет.

Это не баг расчёта, а цена хранения чисел в git, и она уменьшается сама: PR,
который добавляет сервис или образ, всё равно перегенерирует артефакты в рамках
своей ветки. Ловится гейтом, лечится `./scripts/status-badges.sh` и коммитом
с пересчитанными значениями. Полностью исчезает вместе с переездом на shields
`dynamic/json`: там число считается при отрисовке, а не хранится.

## Детерминизм

Скрипт не ходит в сеть, не читает время и не спрашивает кластер. Всё, что не
выводится из содержимого репозитория, в артефакты не попадает: дата генерации,
имя последнего коммита, количество рестартов пода. Иначе `git diff` после
перегенерации показывал бы расхождение на каждом коммите, и гейт начал бы
падать сам по себе.

Когда появится публичное зеркало на GitHub, те же значения можно отдавать в
shields через `dynamic/json` с `url` на `status.json` — расчёты не поменяются,
появится только живое обновление вместо бейджа-файла.

# Jitsi Meet

Приватный сервер видеоконференций доступен по адресу
`https://meet.example.com/`. Веб-интерфейс проходит через Traefik,
а Jitsi Videobridge принимает медиатрафик на `192.0.2.10:10000/udp`.

Сервис рассчитан на клиентов домашней сети и tailnet. Публичный DNS и порты на
роутере не требуются. Удалённый клиент должен использовать DNS Technitium и маршрут
Tailscale к `192.0.2.10/24`, как описано в [`../tailscale/README.md`](../tailscale/README.md).

## Подготовка

На сервере выполнить:

```sh
cd /home/artlab/projects/homelab/jitsi
./init.sh
docker compose pull
docker compose up -d
docker compose ps
```

`init.sh` создаёт каталоги в `$APPS_STORAGE_PATH/jitsi` и игнорируемый `.env` с
правами `0600`. Повторный запуск не перезаписывает существующие секреты. Jitsi
также входит в общий оркестратор инициализации:

```sh
bash scripts/bootstrap-platform.sh
```

Версия `stable-11146-1` закреплена для всех четырёх образов. При обновлении менять
`JITSI_IMAGE_VERSION` нужно одновременно в `.env.example`, `init.sh` и серверном
`.env`, а затем заново проверить звонок между двумя устройствами.

## Rootless-контейнеры

Начиная с `stable-11146` все сервисы запускаются от непривилегированного
пользователя uid/gid 1000 с read-only файловой системой контейнера; конфигурация
из `/config` только читается, а запись идёт в `storage/` и `tmp/`:

- `storage/prosody` — данные Prosody (аккаунты), монтируется в `/var/lib/prosody`;
- `storage/web` — TLS-материалы web;
- `storage/transcripts` — транскрипты;
- `tmp/web-crontabs`, `tmp/web-load-test` — рантайм-файлы web.

Веб-интерфейс слушает порт `8000` внутри контейнера (Traefik направляет на него),
внешние порты не публикуются. Порт медиа `10000/udp` привязан к `192.0.2.10`.

Каталоги `storage/` и `tmp/` должны быть доступны на запись пользователю с uid
1000 (на сервере это `artlab`). `init.sh` создаёт их с правами `0770`. При
обновлении со старой root-схемы данные Prosody переносятся в `storage/prosody`
(на первом старте это делает сам контейнер), а владение каталогами нужно
перевести на пользователя с uid 1000.

## Учётная запись организатора

Создать пользователя, которому разрешено открывать новые комнаты:

```sh
docker compose exec prosody prosodyctl --config /run/prosody/config/prosody.cfg.lua \
  register user meet.jitsi 'заменить-на-случайный-пароль'
```

Пароль не записывать в репозиторий или README. Первый участник входит с этой
учётной записью и создаёт комнату; остальные подключаются как гости по ссылке.

## Качество видео

Веб-клиент запрашивает до `1920x1080`. Для Full HD задан предел `2,5 Мбит/с`
для AV1/VP9 и `3,5 Мбит/с` для VP8/H.264. Адаптивный режим Jitsi остаётся
включённым: фактическое разрешение зависит от камеры, размера плитки участника,
производительности клиента и доступной полосы. Jitsi Videobridge не кодирует
видео заново, поэтому увеличение разрешения нагружает клиентские устройства, а
не CPU сервера.

## Проверка

```sh
dig +short @192.0.2.10 meet.example.com A
curl --resolve meet.example.com:443:192.0.2.10 \
  -o /dev/null -sS -w '%{http_code}\n' \
  https://meet.example.com/
docker compose ps
docker compose logs --since=5m
```

Ожидаются DNS-ответ `192.0.2.10`, HTTP `200` и работающие контейнеры `web`,
`prosody`, `jicofo` и `jvb`. Полная проверка требует звонка между двумя
устройствами: HTTP-проверка не подтверждает прохождение UDP-медиатрафика.

## Сетевая модель

- TCP `443` завершается на Traefik и передаётся контейнеру `web`.
- UDP `10000` привязан только к LAN-адресу сервера и передаётся `jvb`.
- `JVB_ADVERTISE_IPS=192.0.2.10` сообщает браузерам адрес медиамоста.
- STUN отключён: публичный адрес не нужен в приватной сети с маршрутизацией.
- TURN не настроен. Для гостей без Tailscale понадобится отдельное решение с
  публично доступным JVB либо coturn; просто открыть веб-сайт наружу недостаточно.

SELinux и firewalld не отключать. Если firewalld блокирует UDP `10000` внутри
LAN/tailnet, открыть только этот порт для доверенных зон после проверки текущих
правил.

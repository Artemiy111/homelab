# Restic

Restic создаёт зашифрованные дедуплицированные снимки `/storage/apps` и рабочей
копии конфигурационного репозитория. В копию входят локальные `.env`, но не
входит `.git`. Сейчас репозиторий Restic по умолчанию находится в
`/storage/backups/restic` на том же диске сервера.

Каталог `/storage/apps/local-ai/models` исключён: модели занимают около 203 ГБ,
могут быть загружены повторно и не должны дублироваться на том же диске.

> Это защищает от случайного удаления и неудачного обновления приложения, но не
> от отказа диска, кражи, повреждения файловой системы или потери сервера. При
> первой возможности следует перенести `RESTIC_REPOSITORY_PATH` на другой
> физический диск либо использовать удалённое хранилище.

## Инициализация

```sh
cp .env.example .env
chmod 600 .env
sudo install -d -m 0700 /storage/backups/restic /storage/apps/restic/cache
docker compose run --rm init
```

Нельзя терять `RESTIC_PASSWORD`: его резервную копию нужно хранить вне сервера.

## Использование

```sh
# Создать снимок
docker compose run --rm backup

# Показать снимки
docker compose run --rm snapshots

# Применить политику хранения и освободить место
docker compose run --rm forget

# Проверить метаданные репозитория
docker compose run --rm check

# Восстановить последний снимок в изолированный каталог
docker compose run --rm restore
```

Восстановление по умолчанию выполняется в `/storage/apps/restic/restore` и не
перезаписывает рабочие данные.

Резервную копию следует создавать перед каждым обновлением приложения. После
инициализации репозитория и пробного восстановления можно добавить systemd timer.

Для надёжной копии работающих баз данных может потребоваться специальный dump
или краткая остановка сервиса. В частности, до настройки dump-задач эту схему
нельзя считать полной резервной копией приложений на PostgreSQL.

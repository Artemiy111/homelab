# Uptime Kuma

## Запуск

Создать файл окружения и каталог данных:

```sh
cp .env.example .env
sudo install -d -m 0750 ${APPS_STORAGE_PATH:-/storage/apps}/uptime-kuma/data
docker compose up -d
```

Завершить первоначальную настройку учётной записи по адресу
`https://kuma.example.net/`. Те же логин и пароль записать в локальный
`.env` сервиса:

```dotenv
UPTIME_KUMA_USERNAME=user
UPTIME_KUMA_PASSWORD='секретный-пароль'
```

Файл `.env` не отслеживается Git и должен иметь права `0600`.
Одинарные кавычки обязательны, если пароль содержит `$`: иначе Docker Compose
попытается подставить переменную окружения и передаст сервису другой пароль.

## Декларативные мониторы

Желаемое состояние находится в `monitors.json`. Gatus (`gatus/config/config.yaml`)
— источник правды: Kuma зеркалит его там, где это возможно, поэтому URL и
ожидаемые статусы мониторов должны совпадать с эндпоинтами Gatus.

Основные HTTP-проверки обращаются к пользовательским HTTPS-адресам сервисов: одна
проверка охватывает локальное DNS-разрешение, сертификат, маршрут Traefik и ответ
приложения. Сервисы, публичный маршрут которых закрыт forward auth (oauth2-proxy),
Kuma, как и Gatus, проверяет напрямую в Docker-сети (WUD, Cup, Structurizr).

Отдельными мониторами проверяются:

- DNS-запрос непосредственно к Pi-hole (то же имя, что и в Gatus — `uptime.<домен>`);
- опубликованные TCP-порты Gitea SSH и Xray;
- Sure по LAN-порту, поскольку он пока не подключён к Traefik.

Проверка Xray proxy egress (HTTPS через прокси `192.0.2.10:8440`) есть только
в Gatus: Uptime Kuma не управляет прокси из `monitors.json`.

Самопроверка Uptime Kuma обнаруживает поломку её HTTPS-маршрута, но не может
уведомить о полном падении самой Kuma или всего сервера. Для такого сценария
нужен монитор с другого устройства или из внешнего сервиса.

Применить конфигурацию:

```sh
docker compose --profile tools run --rm configure
```

Команда идемпотентна: она создаёт отсутствующие мониторы и обновляет изменённые.
Существующие мониторы сопоставляются по имени. Мониторы, удалённые из
`monitors.json`, автоматически не удаляются, чтобы случайно не потерять ручную
настройку и историю проверок.

После изменения конфигурации выполнить команду повторно. Для добавления нового
типа сначала расширить проверку входных данных в `sync-monitors.mjs`.

Сокет Docker намеренно не подключён. Мониторы HTTP, TCP, ping и DNS работают
без передачи Uptime Kuma контроля над Docker daemon.
